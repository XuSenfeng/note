# QMD

**QMD (Query Markup Documents)** 是由 Shopify 创始人 Tobi Lütke 开发的**完全本地化 CLI 搜索引擎**，专为个人文档、笔记、会议记录和知识库设计。它的核心定位是 "on-device search engine for everything you need to remember"—— 所有数据和计算都在本机完成，不依赖云端 API。

**核心价值：**

- **隐私优先**：纯离线运行，文档从不离开本机
- **三层混合搜索**：BM25 关键词 + 向量语义 + LLM 重排序，精准度远超单一检索方式
- **Agent 友好**：内置 MCP 协议支持，可直接作为 Claude Code、Cursor 等 AI 助手的知识检索后端
- **开箱即用**：模型自动下载，三行命令完成索引和搜索

QMD 依赖三个本地 GGUF 量化模型，通过 `node-llama-cpp` 在 CPU/GPU 上推理：

数据来源：QMD 官方 README 及社区实测报告

![image.png](https://picture-01-1316374204.cos.ap-beijing.myqcloud.com/lenovo-xiangong/20260914113841718.png?imageSlim)
- 三个模型磁盘合计约 **2.04 GB**，运行时（含模型权重 + KV cache + 推理上下文）合计约 **2.85 GB**
- 加上 Node.js 运行时、SQLite 缓存和索引数据，**总内存占用约 2.5–3 GB**
- 推荐机器配置 **8GB+ RAM**，在 16GB/32GB 机器上运行无压力

QMD 提供三种搜索命令，资源开销差异显著：

| 模式           | 命令            | 需要的模型        | 内存     | 延迟                         | 适用场景               |
| ------------ | ------------- | ------------ | ------ | -------------------------- | ------------------ |
| **BM25 关键词** | `qmd search`  | 无            | ~120MB | <10ms                      | 精确术语、代码符号、错误信息、ID  |
| **向量语义**     | `qmd vsearch` | embedding 模型 | ~550MB | 50-200ms                   | 概念相似、同义词、模糊描述      |
| **混合 + 重排序** | `qmd query`   | 全部三个模型       | ~2.8GB | 200-500ms (热) / 最长 21s (冷) | 最高质量、复杂问题、Agent 检索 |


|级别|配置方式|运行内存|4GB 可行性|保留能力|
|---|---|---|---|---|
|**L0 极简**|只用 `qmd search`|~120MB|✅ 毫无压力|纯关键词搜索（SQLite FTS5），不加载任何 AI 模型|
|**L1 轻量**|`qmd vsearch` + 小 embedding|~550MB|✅ 流畅运行|关键词 + 语义向量搜索|
|**L2 中等**|`qmd query --no-rerank`|~900MB|⚠️ 可行，需关桌面|BM25 + 向量 + RRF 融合，跳过重排序模型|
|**L3 全量**|`qmd query` 默认|~2.8GB|❌ 基本不可行|完整混合搜索 + 查询扩展 + 重排序|


### 具体裁剪手段

**1. 跳过重排序（省～900MB）**

```
qmd query "你的问题" --no-rerank
# 或 MCP 调用时传 rerank: false
```

这会跳过 qwen3-reranker-0.6B 模型，直接用 RRF 融合结果输出。

**2. 只用 BM25（零 AI 模型）**

```
qmd search "关键词"
```

完全不加载任何 GGUF 模型，纯 SQLite 查询，内存仅～120MB，在 512MB 设备上都能跑。

**3. 换用更轻量的 embedding 模型**

```
# 默认是 embeddinggemma-300M-Q8_0 (~300MB)
# 可以尝试更小的量化版本或更小模型
export QMD_EMBED_MODEL="hf:Qwen/Qwen3-Embedding-0.6B-GGUF/Qwen3-Embedding-0.6B-Q4_K_M.gguf"
```

Q4 量化比 Q8 省约 40-50% 内存。

**4. 索引时控制批大小**

```
qmd embed --max-docs-per-batch 20 --max-batch-mb 32
```

防止索引过程中内存峰值过高。

**5. 系统层面优化**

- 关闭桌面环境（Jetson/Ubuntu 可省～800MB）
- 禁用不必要的系统服务
- 设置合理的 swap（但 SD 卡 /eMMC 上 swap 很慢，仅作兜底）
