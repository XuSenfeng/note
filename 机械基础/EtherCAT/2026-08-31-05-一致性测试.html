一致性测试

2026-09-02
编辑本页

所有一致性和互操作性测试活动的主要目标，是确保 EtherCAT 设备、EtherCAT P 设备和 FSoE 设备符合 EtherCAT 规范，并在网络中与其他 EtherCAT 设备实现互操作
为确保一致性，应使用 EtherCAT 一致性测试工具（CTT）验证协议一致性

  • Conformance Test = 你自己在实验室拿 CTT 跑，无证书，但必须做
  • EtherCAT Conformance Test = 官方测试中心 ETC 做，= CTT 协议测试 + 互操作性测试 + 物理层测试 + 指示灯/标识人工检查，通过发证书
  • Plug Fest = 多厂商聚在一起互插找问题，不发证书，纯粹是开发期的排雷手段
作用 说明
合规义务 拿了 Vendor ID 就必须订阅 CTT 并自测，哪怕设备只内部使用不外卖。这是 Vendor ID 使用协议的强制条款，不是可选项
质量闸门 Test Record 附录 A 的 128 条测试项本质是一份"从站开发验收清单"，覆盖 ESI、SII、状态机、DC、指示灯、标识、错误计数器
市场准入 / 商业价值 只有通过 ETC 官方测试的设备才能打 "EtherCAT Conformance Tested" 标志和 Logo。终端客户（尤其是欧美和日系 OEM）在招标时会直接要证书

专有名词

组织类

缩写 全称 含义
ETG EtherCAT Technology Group EtherCAT 技术组织,制定规范、管理一致性和互操作性测试
ETC EtherCAT Test Center 官方测试中心(德国纽伦堡/日本大阪/中国北京/美国 Savage),负责官方一致性测试
WG Conformance Working Group Conformance ETG 下设工作组,专门开发和维护 CTT 的测试用例
BUA Beihang University 北京航空航天大学,中国 ETC 的运营方

设备

缩写 全称 含义
ESC EtherCAT Slave Controller 从站控制器芯片(ET1100/ET1200/netX 等),实现 EtherCAT 协议的核心硬件
ESM EtherCAT State Machine 状态机(Init/Pre-Op/Safe-Op/Op),设备必须按 IEC 61158-6-12 规范迁移
ESI EtherCAT Sub/Slave Information 设备描述文件(XML)。注意:老版叫"Slave",新版叫"SubDevice"(见下面术语变更)
SII Slave Information Interface 从站 EEPROM 存储区,保存 ESC 配置、设备标识等。测试里"从 SII 读"=从 EEPROM 读
PDI Process Data Interface ESC 与主 CPU 之间的接口(并行/SPI/32位总线等)
PDO Process Data Object 过程数据对象,即周期性交换的输入/输出数据
SM SyncManager 同步管理器,管理邮箱/过程数据的缓冲通道(SM0-SM3)
FMMU Fieldbus Memory Management Unit 把主站逻辑地址映射到从站物理内存,实现 PD 交换的关键单元
WKC Working Counter 工作计数器,每次帧处理核对数据是否被正确处理
DC Distributed Clocks 分布式时钟(同步),分 DC 设备/非 DC 设备
OD Object Dictionary 对象字典,CoE 设备的数据组织方式
Reg Register ESC 芯片内部寄存器(地址 0x0000 起,如 Reg 0x0150 = PDI 配置)
ENI EtherCAT Network Information 主站生成的网络配置文件,描述整条网段

CTT工具

一致性测试指借助一致性测试工具，对被测设备（DuT）是否符合 EtherCAT 规范进行验证的测试
一致性测试工具是运行在微软 Windows 平台上的软件程序，仅需 100Mbit/s 网卡即可使用

测试流程

章节 测试项编号 内容 自动/手工
A0 测试环境 — 登记 XML 编辑器版本、Schema 版本、配置工具（厂商+Vendor ID+版本）、主站软件、CTT 版本与测试用例文件版本（TF-xxxx） 填表
A1 DuT 信息 — 从 ESC 寄存器/EEPROM/对象字典/ESI 四个来源交叉登记：Vendor ID、邮箱协议支持（CoE/SoE/FoE/EoE/AoE/VoE）、简单/复杂设备（Reg 0x0140.08）、Bootstrap、DC 模式分类、PDI 配置（Reg 0x0150）、ESC 类型（Reg 0x0000-0x0003）、Product Code / Revision / Serial（SII 0x000A/0x000C/0x000E）、HW/SW 版本（OD 0x1009/0x100A） 填表
A2 ESI #1–3 ESI 文件对 XML Schema 校验；Vendor ID 与申请表一致；公司名合规 手工（XML 工具）
A3 CTT 协议测试 #4–7 测试的核心。非 DC 模式跑 2 遍（#4、#5），DC 模式跑 2 遍（#6、#7）。第 2 遍不断电、不重连直接重跑——专门抓"第一次能过、第二次挂掉"的状态残留 bug CTT 自动
A4 指示灯与端口标识 #8–79 占了 72 条，最琐碎。IN 口 / 第 1/2/3 个 OUT 口的标识和 L/A 灯；RUN / ERROR / STATUS 指示灯的闪烁语义（对应 ETG.1300） 手工目视
A5 显式设备标识 #80–108 ID 拨码开关的形式、量程连续性、标签用词；三种机制分别验证：Requesting ID（Reg 0x0134）、Direct ID（IdentificationAdo）、Legacy 模式（Ado=0x0012）、非法 selector 手工写寄存器
A6 分布式时钟 #109–113 主站侧关掉 DC（Reg 0x0980=0）后设备须落回 ErrSafeOp 且 AL Status Code = 0x2C/0x1A；ErrAck 后回 SafeOp；再要 OP 须报 0x2D/0x1A；最小周期时间下能进 OP 并重启 3 次 手工
A7 杂项 #114–122 Device Emulation 位与复杂设备互斥；无 DC 时能进 OP 交换过程数据；拔线后须停留在 SAFE-OP 不报错；错误计数器：PDI 错误计数（Reg 0x030D）=0，各端口无效帧计数（Reg 0x0300/02/04/06）清零后等 60 秒仍须 = 0 手工
A8 半导体行规 #123 Profile 5003，见 ETG7000.2_Anx5003 条件
A9 标识 #124–126 EtherCAT Logo 在设备或文档上；Logo 用法正确；商标声明必须逐字照抄（中文版："EtherCAT® 是注册商标和专利技术，由德国倍福自动化有限公司授权。"）——改一个字就算 fail 手工
A10 互操作性 #127–128 接入 ETC 的异构网络，能被完整扫描；能手动走遍所有支持的状态 手工

判定规则：所有分项全过才算整体通过。CTT 的 warning 不导致 fail，但记录里明确写"期望所有 comment 和 CTT 的 error、warning 都被解决"。

准备（开发早期）

  1. 申请 EtherCAT Vendor ID（ETG 会员区），这是一切的前提
  2. 订阅 CTT / ET9400（Beckhoff 提供工具本体，ETG 提供测试用例文件）。注意：工具是订阅制，必须保持有效
  3. 硬件：一台 Windows PC + 任意 100Mbit/s 网卡即可，不需要专用板卡
  4. 通读 ETG2200 从站实现指南，判据回查 ETG1000_4（链路层/ESC 寄存器）和 ETG1000_6（状态机/邮箱）

厂内自测（Conformance Test，反复迭代）

这是你自己要做的主要工作，把 Test Record 当作开发自查清单逐条打勾：

1) ESI 校验（#1–3）

  • 给 ESI 挂上 Schema，用 XML 工具跑一遍
  • 确认 Vendor ID、公司名

2) CTT 协议测试（#4–7） — 每轮的固定操作序列：

□ 把 ESI 提供给 CTT
□ 若支持，Explicit Device ID selector 设为 0x0005
□ Configured Station Alias 设为 0x0000
□ DuT 断电重上电
□ 重启 CTT
□ 网关/耦合器/模块化设备至少插一个模块
□ 选一个 非DC / DC 模式
→ 跑默认测试集
□ 上传 DuT 的 OD 和 Memory（ESC 寄存器 dump）
□ 工程存为 [测试编号]_CTT_nonDC_1.ctp
→ 不断电、不重连，再跑第二遍，存为 ..._2.ctp

共 4 个工程文件：nonDC_1、nonDC_2、DC_1、DC_2。失败时要在记录里写清是哪个测试文件（TF-xxxx）报的错。
跳过规则：纯 DC 设备跳过 #4–5；不支持 Sync/Latch 的（Not supported / System time only / PDI controlled）跳过 #6–7。
3) 手工项（#8–128） — CTT 测不了的部分，靠目视和手动写寄存器：

  • 指示灯闪烁语义要拿相机或逻辑分析仪确认
  • Explicit Device ID 的三套机制要严格按 >> Instructions 的顺序操作，中间不能插入其他步骤（记录里明确写了 "Instructions shall be followed - No steps between"）
  • DC 异常处理、拔线后停 SAFE-OP、错误计数器 60 秒零增长

4) 覆盖不同特性组合 — ETG.7010 第 6.1 节点名要测：灵活 PDO mapping/assign、各种同步模式
配套读 ETG7000_4 填写指南，里面有配图解释每一项怎么测。

送测前的最终检查

ETG.7010 第 6.1 节的前置条件表，逐项确认：

项 对应文件
☐ Vendor ID 已有 —
☐ 最新版 CTT 自测通过（含各种特性组合） CTT
☐ 符合 ETG.1300 指示灯与标识规范 目录缺，需补下载
☐ 符合 ETG.9001 标识规则 目录缺，需补下载
☐ 按官方 Test Record 完整自查过 ETG7000_2
☐ 家族测试：若成员特性集不同，须有一台支持完整特性集 ETG9003 第 7 章

注意：ETC 按测试当天设备的实际状态测，缺的材料事后一律不许补交。

官方测试流程（ETG.7010 第 6.2 节）

1. 下载并填写申请表 ETG.7030（或 FSoE 用 7031 / EtherCAT P 用 7032）
   → 发到 conformance@ethercat.org
2. ETG 核验 Vendor ID + CTT 订阅有效性 → 分配测试编号 → 转给指定 ETC
   （通常几天内）
3. ETC 发报价和详细信息
   · 之后所有往来直接对 ETC，不再经 ETG
   · 价格由 ETC 定，不是 ETG；排期也直接问 ETC
4. ETC 执行 EtherCAT 一致性测试
5. ETC 把 pass/fail 通知报给 ETG
6. pass → ETG 免费签发 "EtherCAT Conformance Tested" 证书并提供 Logo

测试当天你要提供的东西（ETG9003 第 5.3 条）：ESI、DuT 本体、设备文档、清楚标明所有电气连接的安装手册、配置工具及配套硬件（除 ESI 外不得要求在 ETC 的 PC 上装任何软硬件）、连接器、安装件、电源、其他必要设备。

强烈建议首次送测本人到场协助调试；不到场则设备必须预配置好，让测试工程师无需设备专有知识就能跑起来。

失败了怎么办：可按 ETG9003 第 11 章 申诉，交 ETG 总部转技术顾问委员会，8 周内评估。若问题出在测试用例本身不合理，走 ETG7003 申请 Test Exception。

FSoE / EtherCAT P

  • FSoE：只能对已通过 EtherCAT 一致性测试的设备做。服务方是 TÜV Süd Rail。纽伦堡 ETC 与 TÜV 合作可"一站式"——第一天 EtherCAT，通过则第二天 FSoE。同时申请就把 ETG.7030 和 ETG.7031 一起发。自查用 ETG7011 检查表
  • EtherCAT P：对 EtherCAT P 设备强制，含物理层测试。引入期在德国 ETC 免费（含复测）。申请表 ETG.7032

持续维护

  • 测试用例集在持续增强，可能出现"当初能过、现在过不了"——这是正常的。ETG 的官方立场：设备首次交付客户时通过当时最新版 CTT 即算合规；但鼓励厂商跟进最新版并修复后来暴露的问题
  • 定期看 ETG 会员区的 Test Enhancements 和 Test Exceptions
  • 参加 Plug Fest（每场 20+ 厂商、50+ 产品，通常两天）——发现混装问题最划算的方式
  • 把已通过认证的设备捐给 ETC 的互操作网络（ETG7020），换取持续的问题反馈和协助

扫描描述文件

<EtherCATInfo Version="1.2">                    ← 根元素,版本 1.2
│
├─ <Vendor>                                     ← 厂商信息(第6-9行)
│    ├─ <Id>#x99998888</Id>                     ← 你的 VendID:0x99998888
│    └─ <Name>DC Servo</Name>                   ← 厂商名
│
└─ <Descriptions>                               ← 设备描述(第10行起)
     │
     ├─ <Groups> <Group> ServoDrive ...         ← 设备分组(第11-16行)
     │
     └─ <Devices>
          └─ <Device Physics="YY">              ← 设备声明(第18行起)
               ├─ <Type ProductCode="#x00030001"  ← 产品码
               │      RevisionNo="#x00010000">    
               ├─ <Name>JUXIE_LOWPOWER</Name>    ← 设备名
               │
               ├─ <Profile>                     ← CiA402 伺服配置(22-2426)
               │    ├─ <ProfileNo>402</ProfileNo>   ← 驱动profile 402
               │    ├─ <Dictionary>             ← 对象字典
               │    │    ├─ <DataTypes> ...     ← 数据类型(BOOLEAN/SINT/INT/DT1018/DT1600等)
               │    │    └─ <Objects> ...       ← 对象定义(0x1008/0x1009等 + 伺服参数)
               │    └─ <TxPdo> / <RxPdo>        ← 过程数据定义(见下)
               │
               ├─ <Fmmu>Outputs</Fmmu>          ← FMMU 输入/输出(2427-2428)
               ├─ <Fmmu>Inputs</Fmmu>
               ├─ <Sm> ... </Sm> × 4            ← 4个SyncManager(2429-2432)
               │    ├─ MBoxOut (0x1200, 邮箱出)
               │    ├─ MBoxIn  (0x1480, 邮箱入)
               │    ├─ Outputs (0x1800, 过程数据出)
               │    └─ Inputs  (0x1C00, 过程数据入)
               ├─ <RxPdo> ×2                     ← 接收过程数据(2433-2470)
               ├─ <TxPdo> ×2                     ← 发送过程数据(2470-2514)
               │
               ├─ <Mailbox>                     ← 邮箱服务(2515-2518)
               │    ├─ <CoE DS402Channels="1"    ← 支持CoE + CiA402
               │    │     SdoInfo="1" PdoAssign="1"
               │    │     PdoConfig="1" PdoUpload="1"
               │    │     CompleteAccess="1"/>
               │    └─ <FoE/>                    ← 支持FoE(固件升级)
               │
               ├─ <Dc Unknown64Bit="1" UnknownFRMW="1">   ← 分布式时钟(2519-2534)
               │    ├─ <OpMode> <Name>DC</Name>  ← DC模式
               │    │    <AssignActivate>#x0300</...>
               │    └─ <OpMode> <Name>FreeRUN</Name> ← 自由运行模式
               │         <AssignActivate>#x0</...>
               │
               └─ <Eeprom>                      ← EEPROM配置(2555-2559)
                    <ByteSize>2048</ByteSize>   ← 2KB EEPROM
                    <ConfigData>800C</...>
                    <BootStrap>...</...>

RxPDO 定义了主站发给从站的数据(即"控制伺服"的命令):

对象 内容 类型 位长
0x6040 control word(控制字) UINT 16
0x6060 operation mode(运行模式) SINT 8
0x607A target position(目标位置) DINT 32
0x6071 target torque(目标力矩) UINT 16
0x60FF target velocity(目标速度) DINT 32

你的 TxPDO 定义了从站发回主站的反馈数据:

对象 内容 类型 位长
0x6041 status word(状态字) UINT 16
0x6064 position actual value(实际位置) DINT 32
0x606C velocity actual value(实际速度) DINT 32

把 ESI 喂给 CTT,它用这份描述来测试你的协议一致性。

这个数据是主站使用的, 实际的作用是描述从站的各种寄存器的数据
