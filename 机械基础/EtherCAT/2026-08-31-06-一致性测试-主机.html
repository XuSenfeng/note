ETG 不为主机设备颁发证书

路径 依据文档 结果 认证/证书
A. 主机"互通性验证"(推荐、实操) ETG.1500(主机分级) + ETG.7010(指南) 到 ETC 或 Plug Fest 上跑互联测试 无证书,但有"符合 Class A/B + Feature Pack"的自声明
B. 主机自声明"符合 Master Class" 核对 ETG.1500 的 Table 1 要求清单 对照勾选 无官方证书,靠 vendor 承诺

主要需要关注的是 ETG1500 EtherCAT Master Classes

你不是"测一致性",而是"声明你的主机属于哪个等级(Class)"。ETG.1500 定义了:

主机分两级(第 4 章)

  • Class A:标准 EtherCAT 主机 —— 支持 ETG.1000 系列全部 + ETG.1020 大部分功能,推荐追求的目标。
  • Class B:最小 EtherCAT 主机 —— 功能精简,只要求能跑大部分设备(支持 CoE + 周期 PDO 交换)。只在资源受限(如嵌入式)时允许用。


ETG.1500 §4.3 对 Class B 的定义就是"运行大多数 EtherCAT 设备所需的主要功能(例如支持 CoE、周期性过程数据交换)",并且明确只在资源受限、无法做到 Class A 时才允许宣称(嵌入式系统正是它举的例子)。电机控制器 + 只做 CoE,就是这一档。

Class B 里降为"宜"(should)的,建议你还是做:

  • 502 分段传输:读长对象、字符串、SDO Info 响应超过邮箱长度时必然用到
  • 503 Complete Access:注意——支持 ENI 导入的话这条是 shall。你自己那个 JUXIE 的 ESI 里 CompleteAccess="1",并且 PDO 映射对象整体写入通常就走 CA
  • 504 SDO Info:在线扫描模式下要读从站对象字典,基本躲不开
  • 102 IRQ 位、303 显式设备识别(热插拔/防插错线)、1102/1103 DC 传输延迟与同步窗口监视

测试段的采购清单(+§4.1) ETG7000_3_V1i0i0_D_R_InteroperabilityTestDirective.pdf

文档对从站段有硬门槛,两条前提:

  • 每个从站必须已在 ETC 通过一致性测试——你自己的 JUXIE 不满足这条,不能算入测试段
  • 每个从站必须在默认模式下、无需手动加启动命令就能进 OP

要求覆盖的维度:

  • 拓扑:星型(4 端口设备)、线型(2 端口 MII)、菊花链(3 端口全接)、两从站间 100m 网线
  • ESC 型号:ET1100、ET1200、Altera IP Core、ESC10/ESC20、Xilinx IP Core、netX100、netX50、TI
  • DC:仅 32 位、64 位、无接收时间寄存器三种
  • 标识:直接 ID 机制、请求 ID 机制、无 ID 选择器
  • 过程数据:纯输入、纯输出、输入输出兼有,以及支持 Modules/Slots 的 ESI
  • 邮箱协议:CoE(§4.1.5 只列了 CoE,对你正好)

4.2 还列了一批专门用来踩坑的设备,其中几个对 CoE-only 主站特别值得凑:

  • 默认使能 emergency 对象的设备 / 完全不支持 emergency 的设备
  • 8/16/32 位 ENUM SDO,其中至少一个要有 255 个 ENUM 字符串
  • "慢速"设备:邮箱响应 ≥10 秒,整个对象字典列表传输 ≥30 秒 —— 专门打超时和分段传输
  • 修订号字大小端相反的两种设备 —— 打配置比对(302)
  • 完全中断驱动 PDI 的设备(INIT/PREOP 下不访问 ESC,PDI 看门狗会超时)vs 轮询 PDI 的设备
  • 复杂设备但无过程数据 / 过程数据可变(ESI 里没有 PDO 尺寸信息)/ 仅支持 PDO upload(ESI 里没有 PDO 条目和字典,靠 Mailbox:CoE@PdoUpload=1 + SDO Info)
  • 拒绝 SAFEOP→OP 除非输出 SM 在看门狗超时内被写过至少一次的从站

最后一条几乎是必配 —— 很多自研主站就是在这里卡住,因为它们在切 OP 之前不发过程数据。
